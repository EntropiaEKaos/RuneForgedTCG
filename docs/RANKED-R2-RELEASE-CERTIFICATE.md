## Activation contract

Ranked is intentionally protected by three independent conditions:

1. the deployment environment must set `RANKED_RELEASE_CERTIFIED=true`;
2. runtime game configuration must set `rankedEnabled=true`;
3. PostgreSQL must contain an active Ranked season whose time window is open.

`rankedOperational()` requires the first two. `/api/ranked` additionally requires an open season before it reports `rankedEnabled: true`.

### Safe activation order

1. Deploy the exact release candidate through the certified production pipeline.
2. Confirm `/api/public/game/deployment/provenance` reports the deployed SHA and expected environment.
3. Confirm all database upgrades are applied and exactly one intended Ranked season is open.
4. Set `RANKED_RELEASE_CERTIFIED=true` in the hosting environment and redeploy/restart through the certified pipeline.
5. Confirm `/api/ranked` reports `rankedReleaseCertified: true`, `rankedConfigured: false`, pool `season-zero-r2`, rules `2026.08.97`, and the intended open season.
6. Through the step-up protected LiveOps settings surface, set `rankedEnabled=true`.
7. Confirm `/api/ranked` now reports `rankedEnabled: true`.
8. Execute a production smoke with two controlled player accounts: queue → room → reconnect/resume → settlement → MMR/history.

## Rollback / kill switch

The preferred immediate rollback is **`rankedEnabled=false`** in the runtime game configuration. It closes Ranked without changing the certified deployment artifact.

For a stronger release-level shutdown, set **`RANKED_RELEASE_CERTIFIED=false`** and redeploy/restart. Runtime then fails closed even if `rankedEnabled` was accidentally left true.

Closing/deactivating the active season is a third independent admission stop. In-flight rooms retain their snapshotted season/content certification so settlement remains authoritative.

## Production boundary

This certificate proves the repository/runtime candidate. It does **not** by itself prove that a public hosting origin is currently serving this SHA. Public activation is complete only after the hosted HTTPS deployment reports correct provenance and the post-activation smoke succeeds against the real production PostgreSQL instance.
